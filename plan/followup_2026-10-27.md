## 1. 结论

1. **新发现：P1-L 的 r = 32 oracle 条件没有学会使用记忆。两份评审都没有指出这一点。**
   - 17,000 步时，r = 32 的五个记忆 reader 训练准确率为 0.4–1.6%，loss 为 7.07–7.18，接近无记忆的 B3-L4（0.3–0.4%）；个别 seed 高出最多 1.25 pp（各 run 的数值见 `reports/p1l-c1/training-logs.json`）。
   - Pilot-2 验证集上，全词表 EM ≤ 0.3%；候选准确率 7.2–9.1%，随机水平为 7.1%。
   - 同样设置在 r = 128 能学：M1-L4 为 28.1–41.2%，B8 为 11.3–12.8%，B4 为 10.0–10.8%。
   - Pilot-2 时，交接文档已经记下“r = 32 接近随机”，但当时没有当作设计问题处理。
2. **C1 成立，但只在 r = 32 构成瓶颈。**
   - 机制：LLM oracle 的 key（`pair_codes[e, 0]`）和 value（`global_codes[e]`）是两张独立的随机表。从第二跳起，reader 必须把桥实体的 value 码映射到一个与之无关的 key 码。
   - 数值核查设置：768 个 seen 实体；hop 1 用精确 key；按最近码解码。
   - r = 32：r 个隐藏单元的单步映射只能让 hop-2 寻址达到 48%（线性最小二乘为 30%）。
   - r = 128：同样的映射达到 99.8%。
   - 换成旋转 key `normalize(Π·g_e)` 后，两个 rank 都 ≥ 99%。
   - 因此 rv-fable 说 r = 128 会“因同样原因通过”并不成立。r = 128 下查表不是瓶颈，P1-L 在 r = 128 仍然有效地检验了 reader。区别只在于第二跳起的转移是一张学会的查表，而不是符号 oracle 那样近似恒等的映射。
   - r = 32 连 hop 1 都没学会。这说明另外两处随机映射在 rank 32 下也学不出来：问题状态 → 随机 key，随机 value 码 → 名字。
3. **learned writer 读取失真的原因还没有唯一确定**（rv-astra §4、§8；rv-fable C3）。
   - E = 16 ≤ r 时，存在能精确插值的存储方式。
   - DPFP 一次改变了两个变量：特征几何和查询归一化。
   - 因此先在已有 checkpoint 上做“存储 × 查询 × 解码”的因子诊断，再决定 DPFP 以外的写入方案。
4. **统计与表述问题**
   - 屏选只用了一个 seed（rv-fable C2）。
   - 符号阶段的 pooled 效应掩盖了 seed 间差异，例如 S3 的三个 seed 分别为 +9.3、−17.7、+31.7。C777/C888 被重复使用（rv-astra §3，rv-fable C4）。
   - B8 的参数开销要在每张表里写明：r = 32 为 +8.9%，r = 128 为 +31.0%，符号模型为 +69.2%。
   - OA 是 value/输出通路的上限，不是寻址对照。
   - “组合”只在封闭的 1,024 个名字和训练深度以内成立。
5. **停机与终态**
   - 失败的是事后训练的停机头，不能据此说停机本身不可行。
   - 还没有试过与 reader 一起训练的终态机制（rv-fable C5/R1/R2，rv-astra #6）。
   - 也还没有用“再读一次是否有收益”作为停机标签（rv-astra #3）。
6. **负载**：IS 研究同时改变了负载、图结构和候选分布，所以“干扰”这个解释还没有被单独检验（rv-astra #4，rv-fable C6）。

### F2 RFX（读取失真因子诊断）

- **对象**：WP-L4 的 R/r = 128、R/r = 32 和 W5/r = 32 的最终 checkpoint，全部冻结，不训练。
- **缓存方式**：在 T1 上缓存每个 episode 的 K、V、q（取最后一个问题位置）。只替换这个位置的读取，其他位置不变。
- **因子**：
  - 存储：已部署的 delta，或 ridge `M = V Kᵀ(K Kᵀ + ηI)⁻¹`。η 只在训练 episode 上选。
  - 查询：原始 q，单位化后的 q（尺度在训练集上拟合），或真实的 source key。
  - 对照：干净 value，零记忆。
  - 解码：在训练集读取结果上重新拟合的线性解码器；原来的干净 value 解码器作对照。
- **数据**：拟合用 train 划分。评估用 val 划分中此前没用过的新区间。指标为全词表 EM、归一化读取误差和读取头准确率。
- **决策规则**（2026-10-27 11:05 登记于 `docs/prereg/RFX.md`）：
  - “救回”的定义：归一化读取误差减半，且 EM 提高 ≥ 10 pp。按以下顺序取第一个成立的判定。
  - **存储**（触发 F4 的 K4 和 RG 臂）：ridge + 原始 q 能救回；或者 ridge + 单位 q 能救回，而 delta + 单位 q 不能。
  - **归一化**（触发 F4 的 U 臂）：delta + 单位 q 能救回。
  - **查询**（不做 F4，把寻址方向记为后续候选）：delta + 真实 key 能救回。
  - **存储 + 查询**（不做 F4，只报告）：只有 ridge + 真实 key 能救回。
  - **解码**（不做 F4）：重新拟合的解码器比“限定在 1,024 个实体上的 EM”高 ≥ 10 pp。
  - 都不成立 → 无法区分。
- 登记时相对原计划的修改：
  - 原计划的规则没有覆盖“只靠查询单位化就能救回”的情况。
  - 原计划的“查询”判定会被 ridge + 真实 key 触发，但这一格几乎就是干净 value 对照。
  - 原计划拿解码器的实体准确率和全词表 EM 比，偏向“解码”判定。
- 单位化查询这一项单独给出“归一化”的作用，也回应了 rv-astra 对 DPFP 的批评。
- **结果（2026-10-29 00:5x，wp/llm 379fccd，`reports/p1l-rfx/summary.json`）**：判定 R-r128 与 R-r32 均为“存储+查询”（只有 ridge 存储加真实 key 才救回），W5-r32 为“无法区分”；实体 EM 守卫通过，42 格的全词表命中/实体未命中均为 0。`lsq_arms` 为空，F4 LSQ 不运行。

### F5 WP-L6（LLM oracle 编码 pilot）

- **设定**：
  - r = r_mem = 32；reader 为 M1-L4，lr 3e-3（P1-L 在 r = 32 选出的 lr）；seed 17。
  - 训练 5,666 步，与 P1-L Pilot-2 相同。
  - T2 任务与 P1-L 完全相同，memory-only。
  - val 1000 episodes（seed 4242）。
- **两个臂**：
  - (a) O-rot：key = normalize(Π_rel · g_e)，Π_rel 是每个关系固定的随机正交矩阵；value = g_e，是固定随机码，与 P1-L 相同。
  - (b) O-shared：可学习码表 C，初始化为 g；key = normalize(Π_rel · C_e)，value = normalize(C_e)。码表与 reader 一起训练，计为 writer 参数，各臂相同。
- **参照**：P1-L Pilot-2 的 M1-L4（lr 3e-3），hop-1 EM 为 0.1%，不重跑。
- **通过标准**：最终 checkpoint 在 L = 4 下的 hop-1 val 全词表 EM ≥ 30%。
- **选择规则**（只看 hop 1，不看 hop 2/3）：
  - O-rot 通过 → 选 O-rot，因为它是固定码，最接近已登记的 oracle。
  - O-rot 不通过、O-shared 通过 → 选 O-shared。
  - 都不通过 → LLM r = 32 的 oracle 线停止，论文报告“rank 32 下 LM 通路学不会这类 oracle 编码”。
- **解读**：O-rot 只修第二跳起的转移。如果只有 O-shared 通过，说明 r = 32 的瓶颈在 LM 两端的随机映射。这与 LL3 中可学码表达到 98.7% 的结果一致。
- **结果（2026-10-29 00:4x，wp/oracle 98d048c，`reports/wp-l6/decision.json`）**：按登记规则判为 **stop**。hop-1 val 全词表 EM（L = 4，最终 checkpoint）：O-rot 0.1%，O-shared 11.8%，都低于 30%。两臂都跑满 5,666 步，共约 0.97 node·h。F6 P1L-S 不运行；论文按登记写“rank 32 下 LM 通路在此预算内没有学会这两种 oracle 编码”（一个 seed、一个 lr、5,666 步，不是不可能性的证明）。O-shared 高于 O-rot 只作描述，不作选择。

### F8 IVD（干扰与难度分离，符号）

- **对象**：已有的 r = 32 M1/B4 checkpoint（oracle_random 和 joint_fact），不重训。
- **设计**：
  - 固定目标链、问题和答案集合。
  - 加入路径外的事实，从同一个答案集合中抽取。
  - 2 × 2 交叉：低/高额外负载 × 低/高 key 重叠。oracle 码下直接构造重叠；learned 码下按实测重叠挑选。
  - 匹配相关事实的写入时间和顺序，另加只有衰减的对照。
  - 使用新的确认集。
- **决策规则**：负载相同时，高重叠比低重叠多降低 L4−L1 收益 ≥ 5 pp（配对 CI > 0）→ 干扰解释成立；否则撤回用“干扰”解释 IS 结果。

### F9 CVH（继续价值停机头，符号）

- **对象**：冻结的 r = 32 oracle 和分解式 M1 checkpoint，3 个 seed。
- **比较三种停机头**：
  - 已有的正确性停机头。
  - 同一个头，但在验证集上加“hop 1 不损失”的阈值选择。
  - 同样大小的新头，标签是“之后某一步的目标 loss 是否比当前好出一个固定 margin”；推理时只用当前状态的特征。
- **参照**：固定深度 L1/L4/L16。
- **决策规则**（新确认集）：
  - hops 2–3 比 L1 高 ≥ 3 pp（CI > 0），hop-1 损失 ≤ 1 pp，平均执行深度 ≤ 8。
  - 只有端到端实测的停机延迟优于固定 L16 时，才声称延迟上的改进。
  - 如果验证集上没有阈值能保持 hop 1，判为失败，不再查看确认集。

### F10 TSM（终态语义训练，符号）

- **共同设定**：r = 32；writer 为 oracle_random 和 joint_fact；reader 为 M1；3 个 seed；训练 hops 1–3。
- **三个臂**：
  - T0：M1-L4，用同一代码版本重新训练，作参照。
  - T1：L = 8 训练，在每个 s ≥ hop 的步上都加答案 loss（stay；rv-fable R2，与 rv-astra #6 类似）。
  - T2：T1 加内容门控的粘滞更新：z^{s+1} = z^s + g_s(f(z^s) − z^s)，g_s = σ(a·‖UMQz^s‖/‖u‖ + b)（rv-fable R1）。
- **深度收益对照**：同 rank 的 B4。
- **决策规则**（新确认集）：
  - 该臂 hops 1–3 在 L16 与在 L4 相差 ≤ 1 pp。
  - hops 4–8 相对 T0 的下降不超过 1 pp。
  - 相对 B4 的深度收益 ≥ 3 pp（CI > 0）。
