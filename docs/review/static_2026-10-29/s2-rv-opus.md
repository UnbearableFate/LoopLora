## Verdict

I found no High finding. As written, the paths that determine registered numbers and decisions match the registration:
- the typed wrapper: stratify before the swap, XOR on every fact and question relation, both IDs kept;
- disjointness, including S1B A1's 576,000-episode prefixes;
- `last_valid_question` positions, c and p0 formation, and the common module-named initialization;
- the Role, Step and NULL losses with the CE mask; the soft and hard NULL controller;
- LR pilot and dev selection;
- whole-episode bootstrap, quantiles 1/(240K) and exact integer contrasts;
- sealing through `Permit` and `open.json`.

There are three Medium findings:
1. The lock's `src` digest skips the non-`.py` files in `src/`, so the name asset that renders text and sets answer and Unknown token IDs is unbound.
2. The §3 interface audit (key top-1 and margins by relation, raw read against the true value, frozen value head, relation-flip c) is not recorded anywhere, and the calibration job records only B=0 answer outputs.
3. Several registered descriptive outputs are not produced by locked code. The soft/hard pilot diagnostics for Null are never saved.

There is also one boundary-only float issue in the terminal screens, plus Low items in records and tests. All of these should be fixed before the preflight, because any later `src` or script change voids the lock.
