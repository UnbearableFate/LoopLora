## 2. Critique

**C1 (highest priority). The LLM oracle condition is not the symbolic oracle condition, and at r = 32 it may fail
for a reason unrelated to the reader.** In the symbolic oracle (`sym/writers.py`, `sym/model.py`) the question
encoding, the keys, the values and the output logits all live in one code table: `u = codes[start]`,
`key = codes[head]`, `value = codes[tail]`, `logits = output · codes`. Every map the reader must learn
(Q, Q∘U, B) is identity-like and generalises over all 1,024 entities. In the LLM oracle (`llm/oracle.py`, WP-C7,
LP2) keys are independent random unit codes per (entity, relation) pair and values are the entity codes. The
hop-1 query can come from the LM state through A (2048 → 32, solvable for 1,024 names), but every later hop
needs `Q∘U` to send the bridge entity's value code to an unrelated random pair code, for 1,024 entities, with a
32 × 32 (or 128 × 128) map. Back-of-envelope (least squares on N = 1,024 random pairs in r dimensions): the fitted
address has inner product ≈ r/N with the true key against noise of std ≈ 1/√N from the other ≤ 11 episode keys,
i.e. ≈ 1σ at r = 32 (near chance) and ≈ 4σ at r = 128 (reliable). B8 must learn the table at each step; B4 never
needs it. So G1-L (B8@4 − B4@1 on hops 2–3) at r = 32 measures table memorisation, and the r = 128 replication
would "pass" for the same reason: the spurious-failure/spurious-success trap of [40]. Checkable in seconds (fit
the least-squares map from `global_codes[e]` to `pair_codes[e, 0]`; report cosine and top-1 among 12 keys),
fixable at no compute (E1), and still pre-result because P1-L has not run.

**C2. LLM writer screens cannot support the comparisons drawn from them.** LL5–LL9: one seed, 1,000 validation
episodes (binomial SE ≈ 1.5 pp at 30%), unequal timing-derived budgets, final rather than best checkpoint, lr
fixed at 3e-3 at both ranks. "R beats W5" (33.5 vs 29.9) is ≈ 1.7 SE. OA (LL6 note) bypasses the memory read
entirely, so "oracle addressing" is a misnomer: it bounds value encoding plus output path. The missing control is
an oracle *query* (q = true key, learned M and V), which splits the 84 → 33 gap into query error versus write
interference at no training cost (E3).

**C3. The DPFP registration targets the symptom.** With E = 16 ≤ r the keys are linearly independent and an
exact interpolating store exists (Prop. 11: `a → e_i` under the least-squares solution); DPFP's documented
benefit (Schlag et al., lit_check) is capacity when associations exceed the key dimension, not T1's regime. The
prereg also deviates from Schlag et al. (L2 instead of sum normalisation), inherits lr 3e-3 untested at key
dimension 768, and closes further writer screens, so alternative writers must join this registration before it
runs (W1, W2).

**C4. Symbolic statistics and confounds.** S3's pooled Q = +7.8 hides per-seed +9.3/−17.7/+31.7; B1's seed 29 is
negative throughout, so "the learned writer composes" at r = 32 rests on two of three seeds. S8 confounds rank
with 20,000 vs 15,000 steps. FR1/LP3: the primary P1-L gate compares B8 (+8.9% parameters; +69% in the symbolic
model) with B4; only M1-L4 vs B4 is the equal-parameter test the comparison policy names, yet M1-L4 is secondary.
C777/C888 were reused, so replications on them are not independent. Discrepancy 9: candidate-restricted
accuracy (symbolic) and full-vocabulary EM (LLM) are different quantities; hop-2 single-read accuracies of 1–2%
at L = 1 (S12) are below the 1/14 chance line, i.e. the single read is systematically wrong (the 1-hop
neighbour), so D partly measures escape from that error. Report the neighbour-confusion rate.

**C5. Halting and stability.** HL1–HL4 (post-hoc heads) and H1–H3 (label-free rules) agree with [5]: post-hoc
readouts cannot repair a trajectory trained without a stopping prior; the untested design is a gate trained with
the reader. JS penalises the spectral radius at the final state while Prop. 3 requires expansion along the walk;
the JS3 cost on hops 4–8 follows from that conflict, and H3's 0/96,000 certificates follows from Prop. 7 and says
nothing about terminal-state stability.

**C6. Memory load.** IS3 (retraining at E = 24/36 is worse) uses the E = 12 learning rate and step count; it is
an optimisation confound, and the ledger says so. The "no failure boundary" wording should be replaced by the
measured slope of D(E).

**C7. Readouts.** LP5's J-lens directions are name-logit gradients, not the published transport Jacobian
(noted in lit_check); [11,12] show lens readability is decoder- and block-dependent. Keep the random-direction
baseline, report both decoders, and infer no pointer-chasing from readability.

**C8. Framing gaps.** The draft does not engage the two-hop literature [40–48], test-time-regression memories
[14,25–27] or retrieval-in-weights precedents [29–34]; "composition" is over a closed 1,024-name vocabulary, and
no unseen-entity test exists although `data/relations.py` has seen/unseen pools.

## 3. Proposals, ranked by expected value per node·h

| # | Proposal | node·h | Why first |
|---|---|---|---|
| E1 | Structured oracle keys + unseen-entity endpoint in P1-L (amendment before Pilot-2) | 0 (+3 optional contrast) | Protects the 16 node·h P1-L study from C1 |
| E3 | Oracle-query control on existing WP-L4 checkpoints | 0.1 | Localises the writer failure before spending on fixes |
| W1 | Least-squares (ridge) store and Kaczmarz sweeps, added to the DPFP registration | 4–8 | Exact fix for the diagnosed read distortion (Prop. 11, [14]) |
| R1 | Content-gated sticky terminal state, trained with the reader | 1.5–2 | Only untested design for overshoot; [3,5,50,51] |
| W2 | Slot memory with softmax read | 2–4 (+1.5 symbolic) | Uses existing 88.5% addressing; numeric prediction |
| R2 | "Stay" (progressive) training at L = 8 | 1 | Cheap partial fix; [3] |
| W3 | Factorised keys (head position) + W5/R auxiliaries | 2–4 | Raises the value ceiling (LL2 probes) |
| E2 | Statistics for screens; unseen-entity split for learned writers | 2 per selected arm; 0.5 | Needed for any claim |

All jobs ≤ 1 node × 2 h except the already-registered P1-L main runs.

**E1 — Oracle keys as a fixed rotation of the entity code.** Replace `pair_codes[e, rel]` by
`normalize(Π_rel · global_codes[e])` with Π_rel a seeded random orthogonal 32 × 32 (128 × 128) matrix per
relation. Same-head relations keep distinct addresses (inner product ≈ N(0, 1/r)), and the hop-≥2 map becomes the
single rotation Π_0, which `Q∘U` can represent at any rank; this is the LLM analogue of the symbolic oracle up to
a rotation. Prediction: with the current pair codes the hop-2 reach of B8@4 at r = 32 is < 10 pp and at r = 128
> 30 pp, M1-lin > M1; with rotated keys both ranks give reach > 30 pp and the rank gap shrinks below 10 pp.
Check before Pilot-2: least-squares fit of the value → key map over the 1,024 entities for both key schemes
(cosine, top-1 among 12). Add the endpoint "reach on unseen-pool entities" (train on a seen pool, evaluate on
held-out names; `relations.py` supports it): equal to in-pool reach under rotated keys, at chance under random
pair codes. Optional contrast: B8 and B4 × 3 seeds at r = 32 with the old keys (≈ 3 node·h). Risk: it amends a
registered design; it is pre-result, and it restores the prereg's own "as in P1-S" equivalence.

**E3 — Oracle-query control.** On the WP-L4 R and W5 checkpoints (r = 32, 128), evaluate with q replaced by the
stored key of the queried fact (true index known), everything else deployed. Decision: EM(OQ) ≈ EM(OA) ⇒ the
query path is the bottleneck (then W3/addressing work matters); EM(OQ) ≈ EM(R) ⇒ write interference dominates
(then W1). Cost ≈ 0.1 node·h (evaluation only).

**W1 — Exact-interpolation store.** Arms at r = 32 and 128 on T1 exactly as DPFP: (a) ridge least squares
`M = V Kᵀ (K Kᵀ + λ_r I)⁻¹` over the episode's E facts (recency weights λ^{E−i} keep the decay semantics for
`t3_update`; last-write-wins on duplicate keys), differentiable through the solve; (b) K4: the existing β = 1
delta scan repeated four times over the fact list (Kaczmarz), no new maths, converging to the same interpolant
[17]. Queries unit-normalised as [14] recommends. Prediction: deployed read error < 0.1 (from 0.63) and read-head
accuracy within 5 pp of the clean head (93.3%) at r = 128, so val EM ≥ 0.80 if top-1 addressing stays at 88.5%;
if read error < 0.1 but EM < 0.50, the fault is the query (go to E3/W3). Decision rule and gate as DPFP
(≥ 0.80 select; ≥ 0.50 one E = 8 retrain). Compute: 4 arms × 1 node × 2 h = 8 node·h, or 4 node·h with the
two-per-GPU packing used in WP-L4. Risks: an ill-conditioned Gram amplifies query error (ridge λ_r, query
normalisation, report condition numbers); Props. 5/11 change to least-squares form (Prop. 10 is unchanged: it
concerns values).

**R1 — Sticky terminal state.** `z^{s+1} = z^s + g_s (f(z^s) − z^s)`, `g_s = σ(a·‖U M Q z^s‖/‖u‖ + b)` (a, b
learned), trained with the reader at L = 8 on hops 1–3 with a PonderNet-style step cost [51] and fixed-prior
depth supervision [5]. Past the chain end the memory returns ≈ nothing (oracle) or interference only (learned),
so the terminal state becomes a fixed point without a global contraction penalty. Prediction:
hop-1 at L = 8 within 1 pp of L = 1 (currently −18 to −37 pp for oracle_random/joint_fact), D and W within 3 pp of
M1-L4, and ≥ 80% of terminal states with spectral radius < 1 (JS6: 22%). Experiment: symbolic r = 32, writers
oracle_random and joint_fact, readers M1-L4 and B8 (references) vs M1-L8+gate, 3 seeds, new confirmation set,
metrics D/W/H at L = 4/8/16, 97.5% CIs. Compute ≈ P2-S-F1 scale, 1.5–2 node·h. Risks: gate collapse to step 1
(the reach loss opposes it); at high load the interference read is not small (IS), so report the gate's
threshold transfer to E = 36.

**W2 — Slot memory with softmax read.** Keep K, V, u, the reader and the LM path; store the E pairs (k̂_i, v_i)
and read `Σ_i softmax_i(τ q̂·k̂_i) v_i` (τ learned). State E × 2r floats (4,096 at r = 128, E = 16; smaller than
r² = 16,384). Prediction from LL9: EM ≈ top-1 addressing × clean-value accuracy ≈ 0.885 × 0.933 ≈ 0.83 at r = 128
(≈ OA's 84%) and ≈ 0.82 × 0.85 ≈ 0.70 at r = 32; failure to reach 0.70/0.60 falsifies "addressing is fine, the
superposition is the fault". Two T1 arms (2–4 node·h) plus a symbolic replication of P2-S-F1's multi-read gate
with slot memory (≈ 1.5 node·h) before any P1L-D. Risks: it is attention over compressed facts, so Props. 5,
10, 11 must be re-stated for slot retrieval; `t3_update` needs explicit overwrite-by-key.

**R2 — Stay training.** Train M1 at L = 8 on hops 1–3 with the answer loss at every step s ≥ hop (teaches
"remain decodable after arrival"), oracle_orth and joint_fact, 3 seeds. Prediction: oracle_orth/M1-lin hop-1 at
L = 8 ≥ 95% (S7: 26.3%) without a loss on hops 4–6 at L = 8 larger than 3 pp. ≈ 1 node·h. Risk: like mixed-depth
training (B4) it may lower in-depth accuracy; keep L = 4 evaluation as the reference.

**W3 — Factorised writer with auxiliaries.** W4 (factorised, no auxiliaries) and W5 (auxiliaries, no
factorisation) were tested; their combination was not (LL5). Keys from the pre-tail/head position (probe 95.6%),
values from the tail token (97.6%), with W5/R losses. Prediction: clean-value accuracy ≥ 96% and OA-style
ceiling ≥ 92% at r = 128. Two arms at r = 128 (learned; OA-2pos ceiling), 2–4 node·h.

**E2 — Statistics and generalisation.** Any selecting screen reports binomial 95% CIs on its 1,000 episodes,
matched step budgets, and a second seed for the selected arm (≈ 2 node·h). For symbolic learned writers add an
unseen-pool reach row (≈ 0.5 node·h): composition that survives held-out entities is what [47–49] require.

## 4. Paper

1. Related work: add the two-hop line [40–48], test-time-regression memories [14,16,25–27], slot/lookup
   memories [20–22], retrieval-in-weights precedents [29–34] and looped-model overshoot [3,7,8].
2. State the mechanism claim as "a fixed-size associative state read L times composes hops at the same rank",
   with "within the trained depth" (B6) and "over a closed name vocabulary" (C8) as explicit scope; cite [47] for
   why shared weights (M1) rather than B8 is the generalising design even though B8 scores higher.
3. Report overshoot and halting as a quantified instance of a known failure [3,5,7] and JS as the terminal-state
   analogue of [52]; do not present post-hoc halting as a negative result about halting in general.
4. Must-not-say additions: no equivalence between the LLM and symbolic oracle conditions until E1 is applied; no
   unseen-entity claim; B8's parameter overhead in every table where it appears; OA is a value/output ceiling, not
   an addressing control.
5. Per-step readout: pre-specify the chance baseline and both decoders; cite [11,12,54].
